# Tracker — list projection & Applications tab

- `GET /api/applications` returns a lightweight `ApplicationListItem` projection (only the fields the tracker/dashboard render) — the full `Application` document is fetched per-application via `GET /api/applications/{id}`.
- The projection also carries the soonest upcoming, not-completed interview's `NextInterviewAt` / `NextInterviewEndsAt` / `NextInterviewer` (computed via one extra query in `GetAllListItemsAsync`); the list card's "Next" column shows it (accent, rendered `start–end · interviewer` when an end time/name exist) when present, else the last-activity date.
- Status updates patch the React Query list cache optimistically (`setQueryData`) instead of refetching the list.
- The Applications tab (`components/ApplicationList.tsx`) buckets the list into sections by status: **In Motion** (interview-stage feature cards) → **To Apply** (Analyzing/DecidedToApply — the user's own queue) → **No Reply Yet** (Applied + unknown-status catch-all; freshest first, capped at 6 with a "Show all" toggle, and rows silent 30+ days fold into a collapsed muted "Probably ghosted" `<details>` — presentation only) → **The Archive** (Rejected/Withdrawn, collapsed).
- The App shell scrolls to top on PUSH/REPLACE navigations (`ScrollToTop` in `App.tsx`; browser back is untouched) so deep-list → detail navigation lands at the top.

## Active board (`ActivePage.tsx`, nav: "Active")

A kanban view over the same applications, separate from the Applications-tab list above — four columns: Added → Ready → Applied → Interviewing (`IN_PROCESS_STATUSES`/`INTERVIEWING_STATUSES` in `lib/tracker.ts`, shared with the detail page's gate below). Drag-and-drop exists between Added→Ready (drop fires Generate Pack) and Ready→Applied (drop marks Applied); Applied→Interviewing is deliberately **not** draggable — that transition normally happens automatically once mailbot parses an interview-scheduling email. A small pencil-icon button on Applied cards (fresh and archived alike) opens the existing `StatusModal` as a manual fallback for when mailbot misses or misparses that email. Applied jobs silent 14+ days (`APPLIED_STALE_DAYS`) collapse into an "Archived" disclosure row (bordered, icon + count + chevron) rather than cluttering the main list.

## Application detail — analysis gated behind Interviewing

`ApplicationDetailPage.tsx` shows the raw job description (always) plus the AI Analysis/Why-Work-Here/Company-Summary/Company-News blocks — but only once status reaches `INTERVIEWING_STATUSES` (`showFullAnalysis`); otherwise a placeholder explains why. Rationale: the decision to apply already happened at Matches (the hover/expand `AnalysisCard` there), so repeating the same rationale/flags/company-info on the Tracker before an interview is scheduled just repeats something already seen once — the score/verdict in the left rail is enough through Added/Ready/Applied. This is a pure display gate over already-stored `MatchAnalysis`; see `docs/scoring-and-search.md`'s "Full-narrative enrichment" entry for the matching generation-side deferral.
