# Mailbot (Email Sync)

One-shot process: verifies the tracker isn't a demo instance (aborts exit-1 on `demoMode: true` — see `docs/demo-mode.md`), pulls active applications from the API, searches recent Gmail **by the tracked companies' names** (`newer_than:2d ("Acme" OR "Globex")`, built by `BuildCompanyNamesQuery` from `CoreCompany` names; window = `Gmail__LookbackDays`, default 2 — one day of margin for a missed/failed cron run, the `resync` mode is the recovery path for anything older; `Gmail__Query` overrides verbatim), parses matches via `POST /api/emails/parse` (Claude, `PromptSeeds.EmailParser`, prompt-cached — the known-companies/reference-date system prompt repeats across every email in a run), and applies status/interview updates. **No labels or Gmail filters** — search is retroactive, so a company added to the tracker today is covered against the whole window immediately, and the only OAuth scope needed is `gmail.readonly`. (The old label/filter auto-management was deleted; the overlap re-processes some mail each run — DB writes are free by idempotency, but each re-seen email is still a billed Claude call, so the window is kept as tight as the missed-run margin allows.) `GmailEmailService.GetEmailBody` concatenates **all** text parts (every `text/plain` + HTML-stripped `text/html`, capped at 50K chars) — not just the first — so dates/times/interviewer that live inside ATS/calendar HTML cards (eightfold, Google Calendar) reach the parser.

- **Persisted messages (Messages tab)** — every email the parser recognizes as job-related (`update != null`) is upserted to the API as a `TrackedEmail` (`POST /api/messages`, `Core/Models/TrackedEmail.cs` — named that rather than `Message` because `Anthropic.SDK.Messaging.Message` is already in scope alongside `ApplicationTracker.Core.Models` in `ClaudeClient.cs`, and a same-named type there would make every bare `Message` ambiguous). This includes emails `MatchApplication` couldn't tie to a tracked app — persisted with `ApplicationId: null` and flagged in the client rather than silently dropped, so a bad match is visible instead of invisible. Upserted (not inserted) keyed on Gmail's own message id (`GmailMessageId`, captured in `GmailEmailService.ParseGmailMessage`) — the daily sync's overlapping lookback window and re-sync's full-history walk both re-see the same email, and this keeps re-processing idempotent instead of piling up duplicate rows. Persistence failure never blocks the tracker update (`AddMessageAsync` swallows and logs its own transport errors, same retry/backoff as every other `TrackerApiClient` call). `GET /api/messages` (client `/messages` page) is a plain read; `POST /api/messages` is a real write and deliberately **not** in the demo allowlist (the mailbot already refuses to run against a demo tracker — see `docs/demo-mode.md` — so this is defense in depth, not the primary guard).
- **Matching** — an email is matched to an application by **company + job title**. The parser extracts a `jobTitle`; when several applications share a company, `MailbotOrchestrator.MatchApplication` disambiguates by title (exact → substring → token overlap), falling back to the first company match with a logged warning.
- **Interview idempotency** — the create-interview endpoint updates the existing auto-detected interview of the same type instead of inserting a duplicate (multiple emails in one scheduling thread each parse as `InterviewScheduled`), carrying `EndsAt`/`Interviewer`/`Topics` forward on the merge. Scoped to interviews with `Notes == "Auto-detected from email"`; manual interviews are never merged.
- **Interview type → status** — the parser's `interviewType` maps to the application status: `Phone`/`HR` → PhoneScreen, `Technical` → TechnicalInterview, `Final` → FinalRound. The prompt only chooses `Final` when the email **explicitly** says final/last round; an unqualified in-person/"frontal"/onsite interview defaults to `Technical` (so a regular onsite round doesn't read as a misleading FinalRound). `HR` takes precedence over `Phone`: a phone call whose interviewer is a recruiter/TA/HR person is typed `HR` (a TA phone screen was previously typed `Phone`).
- **Status idempotency** — `PUT /api/applications/{id}/status` is a no-op (no `StatusUpdate` row written) when the status is unchanged, so re-processing the same email never appends duplicate "X ← X" timeline rows. The mailbot also has a **no-regress guard** (`MailbotOrchestrator.SetStatusAsync`) that won't move an app to an earlier-stage status.
- **Interview dates & times** — the email parser receives a **reference date** (the email's `ReceivedAt`, sent by the mailbot; else server now) plus day-first / year-less / relative date guidance, so e.g. "28.6" resolves to the correct `YYYY-MM-DD`. `GmailEmailService.ParseEmailDate` strips RFC 2822 `(UTC)`-style trailing comments. When no date is found, the fallback is date-only (no run-clock time). The parser also returns an **optional end time** (`interviewEndTime`) only when the email gives a range (e.g. "2:00–3:00 PM"); the mailbot sets `Interview.EndsAt` from it (null otherwise — **never inferred**). Neither a missing date nor a missing end time is ever guessed. **Times are wall-clock in `Mailbot__TimeZone`** (IANA id, default `Asia/Jerusalem`) and converted to UTC in `CombineDateAndTime` before storage — never interpreted in the server's zone (the Render cron runs in UTC; before this, "14:30" from an email was stored as 14:30Z and displayed as 17:30).
- **Per-application re-sync** — to recover beyond the recent-window sync (missed/mis-parsed email), run the mailbot in re-sync mode: CLI `dotnet run --project server/mailbot -- resync --company "X" [--title "Y"]`, or env `Mailbot__Resync=true` (+ optional `Mailbot__ResyncCompany`/`ResyncTitle`; unset company ⇒ all apps via `RunResyncAllAsync`). It searches the company's **full mail history** (query = `"{CoreCompany}"`, no time limit) oldest→newest and reconciles via the shared `ProcessEmailsAsync`. Candidate apps are matched (and the Gmail search term + parser company list are built) by the **core company name** — a trailing `" - <location>"` is stripped (`CoreCompany`) — so `--company "Applied Materials"` resolves the stored "Applied Materials - Israel". **Reconcile-only & idempotent**: fixes current state, writes only on change, never deletes existing rows. Needs the Tracker API pointed at a **non-demo** instance (DemoMode 403s writes). The mailbot loads a local `.env` (like the API) for `Gmail__CredentialsPath` etc.; in prod Render injects env vars.
- **OAuth token lifecycle** — refresh tokens issued while the Google OAuth consent screen is in *Testing* status expire after 7 days (`invalid_grant: Token has been expired or revoked`); the app is published, so tokens no longer expire. If it ever recurs: delete `%APPDATA%\Google.Apis.Auth\…TokenResponse-user`, run the mailbot locally to re-consent, and paste the fresh cache into Render's `/etc/secrets/gmail-token.json`.
